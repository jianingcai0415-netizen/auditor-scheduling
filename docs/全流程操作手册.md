# 审核员调配系统 — 全流程操作手册

> 适用对象：首次完整跑通「排单 → 分配 → 审批 → 发布 → 存结果 → 复盘」全链路的使用者。  
> 系统地址：<http://localhost:8081（由桌面启动器「启动审核员调配系统.bat」拉起）>  
> 你的账号 jianingCai0415 是管理员，调度员与审批人的按钮都能看到。

---

## 0. 全流程总览

```
① 建/导订单 ──→ ② 找候选(可选) ──→ ③ 生成排程草案 ──→ ④ 逐名额分配+清风险
                                                        │
        ⑦ 发布 ◄── ⑥ 审批(批准/退回) ◄── ⑤ 提交审批 ◄──┘(须 0 缺口 0 风险)
           │
           ├─→ ⑧ 修订(出 v2 → 替代 v1)
           └─→ ⑨ 排班管理页求解/存结果（另一条写入路径）
复盘：⑩ 操作日志 + 方案操作记录 + 已发布方案详情
```

两个核心入口页：

| 页面       | 侧边栏入口  | 干什么                          |
| -------- | ------ | ---------------------------- |
| **审核调配** | 「审核调配」 | 订单、候选、排程方案、审批发布、操作日志（工作流主战场） |
| **排班管理** | 「排班管理」 | 班次时间轴、自动排程求解、保存分配结果          |

## 1. 登录

1. 双击 `scripts/start-windows.bat`（分发包里是根目录的「启动审核员调配系统.bat」）→ 自动开浏览器（服务已在跑时只开浏览器，不会双开）。
2. 登录页输入用户名/密码 →「登录」。
3. **产出在哪看**：进入主界面，左上角显示机构名（Poliambulatorio Centro），右上角有用户菜单与语言切换（中/英）。

> 会话 30 分钟无操作会过期，届时页面会跳回登录页，重新登录即可，数据不会丢。

## 2. 建/导入订单（流程起点）

订单 = 一次审核任务，含若干「阶段」（什么时间、什么地点、需要几个什么资格的人）。

**方式 A：页面上手工建（推荐首次走通）**

1. 审核调配 →「订单与阶段」标签 → 「新建审核订单」卡片，填单号/项目/客户/优先级。
2. 在订单列表里展开该订单 →「添加阶段」→ 填阶段编号、起止时间、地点、人数、是否需要组长审核员、资格技能。
3. 阶段状态须为「就绪」、订单状态为「进行中」才能查候选。

**方式 B：Excel 导入（批量）**

1. 「Excel 导入」标签 → 「下载固定模板」→ 按模板填写。
2. 上传 → 系统先**预检查**：列出每行错误/警告，可「下载错误」修正。
3. 全部错误清零后「确认导入」才会生效。

**产出在哪看**：订单与阶段列表（Accordion 折叠卡片）；顶部仪表卡「进行中订单」计数 +1。

---

## 3. 按单号找候选（分配前的侦察，可选但推荐）

1. 「按单号找候选」标签 → 输入订单号 → 查询。
2. 系统按当前评分规则（能力/位置/负荷/连续性/年龄，权重可调且必须合计 100%）对每个名额给出：
   - **已检查 N 人 / 硬约束合格 M 人**：不合格原因以灰色徽章逐类列出（资格不符/时间冲突/状态不可用/缓冲不足等，鼠标悬停看解释）；
   - 每个名额一张候选表：排名、综合分、五维分项、预计转场分钟、入选理由。
3. （可选）「AI 初筛复核」按钮：需管理员在服务端配置 AI，仅对规则筛出的合格候选做二次排序建议，**不会自动分配**。

**产出在哪看**：本页的候选表。注意提示条：候选是实时推荐，不占用人员；真正占名额要走第 4 步的草案。

---

## 4. 生成排程草案（两条路，选一）

进入「排程方案」标签（也可从顶部「处理草案」卡片直达）。

**路线 A：按订单生成（配合第 3 步，从零开始）**

- 在第 3 步的候选页点「生成该订单排程草案」。
- 特点：从**全部名额未分配**开始，不沿用排班表现有人员——每个名额都要你从合格候选中锁定，过程可控但步骤多。

**路线 B：时间窗快照（最常用的起步方式）**

- 「排程方案」标签顶部的卡片，现在叫「**把当前排班存为快照**」：填**方案名称 + 窗口起止时间** → 点「**存为快照**」。
- 特点：把当前排班表在窗口内的分配**原样复制**成快照，**不改动任何班次**；不合格的现有人员不会被移除，而是在「风险」列标出，你逐项处理。
- 注意窗口取的是「**有交集**」的班次，不是完全落在窗内的：跨边界的多天现场任务也会被收进来，所以名额数常大于窗口内完整班次的数量。
- 窗口内没有班次会报错「窗口内没有班次」；同一窗口重复点「存为快照」会打开**同一份快照**（不会重复建）。

**产出在哪看**：

- 「排程方案」列表新增一行，状态徽章「草案」，三列数字 = **名额数 / 缺口数 / 风险数**；
- 顶部卡片「待排班草案」计数 +1；
- 点「查看」打开详情页：状态流转图 + 人员完成度（已分配 X/Y · 风险 N）+ 分配明细表 + 底部操作按钮。

> **建议首跑**：路线 B + 一个 2~3 天的小窗口（如 12-16 ~ 12-17，班次少、好处理）。

---

## 5. 逐名额分配 + 清风险（草案 → 干净草案）

打开草案详情，逐行处理直到详情页显示 **缺口 0、风险 0**（提交按钮才会亮）：

1. 每行点「换人/重新锁定」→ 弹出候选窗口：
   - 候选按综合分排序，显示转场分钟、风险原因；「选择原因」已预填可直接用；
   - 选中 → 点「选择」。若该人有时段冲突会被拒，换下一位。
2. 风险行的「风险」列有红色徽章（不可用/资格不符/时间冲突/缓冲不足/订单阶段已被修改等，悬停有解释）——全部通过换人清除。
3. 缺口行 = 未分配名额，同样走换人弹窗选人。
4. 中途可「导出 Excel」留档；不想要的草案点「删除草案」（仅草案状态可删，弹窗确认，删除有审计）。

**产出在哪看**：详情页「人员完成度」实时变化（已分配 X/Y · 风险 N）；列表该行的「名额/缺口/风险」数字同步刷新。

> **注意**：页面有实时推送（SSE）——别人改了员工状态，你的打开中的方案会**自动刷新**，新增风险行会立刻标出，批准/提交按钮也会自动置灰。这不是故障，是并发保护。

---

## 6. 提交审批 → 审批 → 发布

前置：缺口 0、风险 0、窗口未结束（过期草案会被禁用并提示「窗口已于 … 结束」）。

1. **提交审批**（调度员动作）：详情页底部按钮 → 状态变「待审批」。
   - 产出：顶部「等待审批」卡片 +1；方案操作记录多一条「提交审批」。
2. **批准 或 退回**（审批人动作）：
   - 「批准」→ 状态「已批准」；
   - 「退回」→ 弹窗**必填退回原因** → 状态回到「草案」，详情页顶部显示「上次退回原因」，操作记录在案。修完可再次提交。
3. **发布**（审批人动作）：点「发布」→ 先弹**确认框**：
   - 列出将写入的班次数；若窗口与已发布方案重叠，有红色提醒「窗口重叠的 N 个已发布方案将标记为已被新版本替代」；
   - 点「确认发布」→ 状态「已发布」。

**最终结果呈现/怎么看**：

| 看什么        | 在哪看                         | 长什么样                             |
| ---------- | --------------------------- | -------------------------------- |
| 发布生效的分配    | 排班管理页时间轴                    | 对应时段的班次上出现人员姓名（这是真实排班数据，不再是草案快照） |
| 方案状态       | 排程方案列表（筛「仅已发布」）或顶部「已发布方案」卡片 | 「已发布」徽章                          |
| 谁在什么时间被派去哪 | 已发布方案详情 → 分配明细表             | 每行：班次时间 + 人员 + 角色 + 来源           |
| 全程留痕       | 「操作日志」标签                    | 提交/批准/发布/换人/删除…每条含时间、操作人、详情      |
| 留档输出       | 方案详情 →「导出 Excel」            | 可发邮件/存档的分配表                      |

## 7. 修订：已发布方案要改人怎么办

1. 打开**已发布**方案详情 →「新建修订」→ 系统克隆出 v2 **草案**（v1 保持已发布不动）。
2. 对 v2 重复第 5~6 步（改人→提交→批准→发布）。
3. 发布 v2 时确认框会提示将替代 v1；确认后：
   - v1 状态变「**已被替代**」，徽章悬停/详情页顶部显示精确说明：「时间窗内的分配已被《xxx》v2 全部覆盖，仅作历史留档」（部分重叠时则说明未重叠区间仍按 v1 执行）。

**产出在哪看**：排程方案列表切「全部状态」可见 v1(已被替代) + v2(已发布) 两行；版本列 v1/v2。

## 8. 排班管理页：自动排程求解 + 保存结果（第二条路径）

适合「不想逐个手选，让求解器全局优化」的场景。**注意：这条路径直接写排班表，不经过审批流。**

1. 排班管理页 → 时间轴上先把**可见时间范围**调到目标窗口（求解只作用于当前可见窗口）。
2. 点绿色「自动排程」按钮 → 遮罩层显示求解中（约几秒到几十秒）。
3. 完成后弹**求解结果窗口**：约束分析（哪些硬约束全部满足、哪些指标有代价）、每个名额的建议人选。
4. 点「**保存分配结果**」→ 才真正写入排班表。
   - 若求解期间班次或人员状态变了，会拒绝保存并提示重跑（并发保护）；
   - 保存有审计记录。
5. **产出在哪看**：
   - 时间轴上人员姓名即时更新（这是最终结果本身）；
   - 审核调配 → 操作日志 →「保存解算结果」条目（含提交数/实际写入数/窗口）。

> 路径关系备忘：**审批流发布**写的是「带来源标记的正式方案」；**求解保存**直接改排班表（改动已发布班次时会清掉其方案来源标记）。日常正式排程建议走审批流；求解适合草案阶段的辅助建议。

## 9. 常见状况速查

| 状况                   | 含义                                | 怎么办                       |
| -------------------- | --------------------------------- | ------------------------- |
| 提交/批准按钮灰的            | 有缺口或风险未清，或窗口已过                    | 看详情页「人员完成度」与按钮悬停提示        |
| 弹红色 toast「有人员状态已更新…」 | 别人刚改了你方案里的人                       | 重开该行的换人弹窗重新确认/换人          |
| 弹「排班已变更」             | 班次数据在操作中途被改                       | 页面会自动刷新，重试一次              |
| 草案想废弃                | 仍在草案状态                            | 详情页「删除草案」（有确认+审计）         |
| 已过期草案                | 窗口结束的草案                           | 不能提交/批准/发布；可删除；列表筛「已过期」查看 |
| 已发布方案自身行显示「订单阶段已被修改」 | 已知显示噪音（发布写班次使版本+1，快照未回写），不影响数据与流程 | 忽略；修订时快照会重新同步（待修复项）       |
